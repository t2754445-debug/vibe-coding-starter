# Скиллы: что это и как сделать свой

> Скилл — это инструкция, которую агент подхватывает сам, когда задача ей соответствует.
> Формат придумала Anthropic, с декабря 2025 он открытый: один и тот же `SKILL.md`
> работает в Claude Code, Codex, Cursor, Gemini CLI.
>
> Практический смысл: **всё, что ты объясняешь агенту второй раз, должно стать скиллом.**

---

## Как это устроено

Скилл — это папка с файлом `SKILL.md`:

```text
~/.claude/skills/
└── мой-скилл/
    └── SKILL.md
```

Внутри — заголовок с описанием и сама инструкция:

```markdown
---
name: telegram-bot
description: Использовать при создании телеграм-ботов на Python — задаёт структуру проекта, библиотеку и правила обработки ошибок
---

# Телеграм-боты

## Стек
- Python 3.12, aiogram 3.x
- Токен только через .env, никогда в коде
- Хранение: SQLite через aiosqlite

## Структура проекта
bot/
├── main.py       — запуск, регистрация обработчиков
├── handlers/     — по файлу на группу команд
├── keyboards.py  — кнопки
└── config.py     — настройки из .env

## Правила
- Каждый обработчик — отдельная функция с понятным именем
- Любой внешний запрос оборачивать в try/except с понятным сообщением пользователю
- Логировать ошибки в файл, пользователю показывать человеческий текст
```

**Ключевое поле — `description`.** По нему агент решает, подключать скилл или нет.
Описание «для ботов» не сработает. «Использовать при создании телеграм-ботов на Python» — сработает.

---

## Чем скилл отличается от CLAUDE.md

| | CLAUDE.md | Скилл |
|---|---|---|
| Когда действует | Всегда, в каждом запросе | Только когда задача подходит |
| Что содержит | Общие правила поведения | Знание про конкретный тип задач |
| Размер | Компактный, читается всегда | Может быть большим — грузится по надобности |
| Пример | «Отвечай на русском, не усложняй» | «Как делать телеграм-ботов» |

Правило: **общее — в CLAUDE.md, специальное — в скилл.**
Если сунуть всё в CLAUDE.md, он раздуется и агент начнёт терять из виду главное.

## Как создать свой за пять минут

Самый простой путь — попросить агента:

```text
Создай скилл в ~/.claude/skills/имя-скилла/SKILL.md

Тема: [например, парсинг сайтов на Python]
Что туда включить:
- стек, который я использую: [...]
- структура проекта: [...]
- правила, которые я повторяю каждый раз: [...]
- типичные ошибки, которых надо избегать: [...]

Description напиши так, чтобы скилл подхватывался, когда я прошу
спарсить сайт или собрать данные с веб-страницы.
```

Руками — то же самое:

```bash
mkdir -p ~/.claude/skills/мой-скилл
code ~/.claude/skills/мой-скилл/SKILL.md
```

Проверка, что скилл виден: в Claude Code набери `/` — он появится в списке.

## Откуда брать готовые

**Маркетплейс плагинов** — встроенный магазин. В Claude Code:

```text
/plugin
```

Официальный набор от Anthropic включает: `feature-dev` (разработка фич),
`code-review` (ревью), `frontend-design` (интерфейсы), `commit-commands` (коммиты и PR),
`skill-creator` (создание скиллов), `mcp-server-dev`, `security-guidance` и другие.
Ставится в один клик, обновляется автоматически.

**Сборники на GitHub** — тысячи скиллов от сообщества:

- [VoltAgent/awesome-agent-skills](https://github.com/VoltAgent/awesome-agent-skills) — 1000+ скиллов,
  совместимых с Claude Code, Codex, Cursor и Gemini CLI
- [hesreallyhim/awesome-claude-code](https://github.com/hesreallyhim/awesome-claude-code) —
  подборка скиллов, агентов, статус-лайнов и инструментов
- [travisvn/awesome-claude-skills](https://github.com/travisvn/awesome-claude-skills) — каталог скиллов
- [ComposioHQ/awesome-claude-skills](https://github.com/ComposioHQ/awesome-claude-skills) — ещё один каталог

Ставятся копированием папки в `~/.claude/skills/`.

**Осторожно со сторонними скиллами.** Скилл — это инструкции, которые агент выполнит.
Читай перед установкой то же, что читал бы в чужом скрипте. Особенно если внутри есть команды.

## Как понять, что пора сделать скилл

Три признака:

1. **Объясняешь одно и то же второй раз.** «Помни, у нас aiogram, а не telebot» — в скилл.
2. **Агент повторяет одну и ту же ошибку.** Не ругайся — запиши правило.
3. **Есть последовательность, которую делаешь регулярно.** Ревью → тесты → коммит → пуш.

Обратный признак — когда скилл делать **не надо**: если правило нужно ровно один раз,
это не скилл, а строчка в промпте.

---

## Сколько скиллов держать

Для примера: в моём рабочем окружении их около 120 — но это накоплено за год работы
и включает целые тематические наборы (SEO, дизайн, тестирование, работа с браузером).

Новичку столько не нужно и даже вредно: чем больше скиллов, тем выше шанс,
что подхватится не тот. Начинать стоит с **трёх-пяти собственных**, написанных под свои задачи,
плюс два-три официальных плагина.

Рабочий подход: **скилл рождается из боли.** Что-то пошло не так, ты объяснил агенту,
как надо — записал это в скилл. Через месяц таких записей набирается десяток,
и они стоят больше, чем сотня скачанных из интернета.

---

## Проверка, что скилл работает

Дай задачу, под которую он написан, и посмотри, подхватился ли он.
В Claude Code видно строку вида `Using skill: telegram-bot`.

Не подхватился — почти всегда дело в `description`. Он должен содержать слова,
которыми ты **реально формулируешь задачу**. Пишешь «сделай бота» — значит,
в описании должно быть слово «бот», а не «мессенджер-интеграция».
