# Стартовый набор: рабочее окружение и методика

> Это не курс и не книга. Это **рабочее окружение**, выжатое из года практики,
> плюс методика, по которой оно применяется.
>
> Файлы читает не только человек, но и AI-агент: положи папку рядом с проектом —
> и он сам настроит компьютер и будет работать по этим правилам.

---

## Как этим пользоваться

### Шаг 1. Настроить компьютер (30 минут, делает агент)

1. Открой эту папку в VS Code: `File → Open Folder`.
2. Запусти Codex или Claude Code.
3. Скажи ему:

```text
Прочитай SETUP.md и выполни всё, что там написано.
```

Дальше отвечай «да» на подтверждения. Агент поставит Homebrew, Git, Node,
расширения VS Code и разложит правила по местам.

### Шаг 2. Прочитать три файла

Именно в этом порядке, всё остальное — потом:

1. `02-методология/01-думать-до-промпта.md` — **главный файл набора**
2. `02-методология/04-промпты-для-агента.md` — шаблоны на каждый день
3. `01-инструменты/terminal-mac.md` — семь команд, чтобы не бояться терминала

### Шаг 3. Сделать первый проект

По плану из `04-программа/занятие-5-часов.md`, блок 2 и дальше.

## Главные мысли, если читать некогда

**Час на продумывание экономит день на переделках.** Пять вопросов до первой строки:
что делает (одно предложение без «и») → кто пользуется → что на входе и выходе →
чего НЕ делает → как понять, что готово.

**По одному шагу.** Пять маленьких запросов дают рабочий результат быстрее одного большого:
в большом ошибка находится в конце, в маленьком — сразу.

**Коммит после каждого работающего шага.** Git — кнопка «отменить» на весь проект.
Две секунды, окупаются в первый же раз, когда агент сломает работавшее.

**Не понял код — он не готов.** Проси объяснить построчно. Непонятый код
через неделю становится неисправимым.

**`CLAUDE.md` — живой файл.** Правило, записанное после своей ошибки, ценнее
десяти скачанных из интернета.

## Чего в наборе нет намеренно

Здесь нет курса по Python, нет справочника по библиотекам, нет списка из ста скиллов.
Всё это гуглится за минуту и без методики бесполезно.

Есть только то, что определяет разницу между «AI написал непонятную кучу»
и «AI написал ровно то, что нужно, и я понимаю каждую строчку».
