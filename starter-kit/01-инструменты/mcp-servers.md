# MCP-серверы: что это и какие нужны

> MCP (Model Context Protocol) — способ дать агенту руки: доступ к браузеру,
> документации, базе данных, внешним сервисам.
> Открытый стандарт, работает одинаково в Claude Code, Codex, Cursor.
>
> Главное правило новичка: **не подключай ничего, пока не упрёшься.**
> Каждый сервер — это лишний процесс при старте и лишние инструменты в контексте.

---

## Зачем это нужно

Без MCP агент умеет: читать и писать файлы, выполнять команды в терминале, искать в интернете.
Этого хватает для 80% задач.

MCP добавляет то, чего в базовом наборе нет:

- посмотреть **актуальную документацию** библиотеки, а не ту, что модель помнит с обучения;
- **открыть сайт в браузере**, покликать, снять скриншот, проверить вёрстку;
- сходить в **базу данных** и посмотреть, что там реально лежит;
- работать с внешним сервисом — Figma, Linear, Stripe, Supabase.

## Три сервера, с которых стоит начать

Ставить по одному, по мере появления потребности.

### context7 — документация библиотек

**Ставить сразу.** Самый полезный сервер из всех.

Модель обучалась до определённой даты. Библиотеки с тех пор обновились: функции переименовали,
параметры поменяли. Агент честно пишет код по старой памяти — и он не работает.
`context7` подтягивает свежую документацию прямо в момент вопроса.

```bash
claude mcp add context7 -- npx -y @upstash/context7-mcp
```

Признак, что он нужен: агент пишет код с несуществующими функциями и уверяет, что всё правильно.

### playwright — браузер

**Когда начнёшь делать сайты.** Даёт агенту настоящий браузер: открыть страницу,
нажать кнопку, заполнить форму, снять скриншот.

```bash
claude mcp add playwright -- npx -y @playwright/mcp
```

С ним работает связка «сделай кнопку → посмотри, как получилось → поправь»,
где агент сам открывает результат и видит свою работу.

### memory — память между сессиями

**Когда проект станет длинным.** Хранит факты о проекте в виде графа знаний,
чтобы не пересказывать контекст в каждой новой сессии.

```bash
claude mcp add memory -- npx -y @modelcontextprotocol/server-memory
```

## Что бывает ещё (обзор, ставить не надо)

Для понимания масштаба — вот что подключают под конкретные задачи:

| Сервер | Для чего | Когда пригодится |
|---|---|---|
| **github** | Issues, PR, репозитории через API | Если работаешь в команде. Для одного проще `gh` в терминале |
| **postgres** / **sqlite** | Запросы к базе | Когда агенту надо посмотреть реальные данные |
| **supabase** / **neon** | Облачные базы | Когда проект уедет на хостинг |
| **figma** | Макет → код | Если дизайнер отдаёт макеты в Figma |
| **stripe** | Платежи | Когда дойдёт до приёма денег |
| **brave-search** | Веб-поиск | Дублирует встроенный поиск, обычно не нужен |
| **filesystem**, **fetch** | Файлы, загрузка страниц | Дублируют встроенные возможности — **не ставить** |

Отдельная категория — серверы под конкретные сервисы: Slack, Cloudflare, Redis, Google Maps.
Подключаются точечно, когда появляется задача.

## Как управлять

```bash
claude mcp list                 # что подключено и в каком статусе
claude mcp get <имя>            # подробности по одному
claude mcp remove <имя> -s user # отключить
```

Область видимости:

- `-s user` — глобально, работает во всех проектах;
- `-s project` — только в текущей папке (файл `.mcp.json` в проекте).

Правило: **глобально держи только то, что нужно везде.** Остальное — в проект,
где оно реально используется.

## Как не устроить помойку

Типичная история: за месяц подключается пятнадцать серверов, половина дублирует
встроенные возможности, старт сессии занимает полминуты, а агент путается
в двадцати похожих инструментах.

Как этого избежать:

1. **Правило одного отказа.** Подключай сервер только после того, как задача
   реально не решилась без него.
2. **Раз в месяц ревизия.** `claude mcp list` → всё, чем не пользовался, отключить.
3. **Не ставь дубли.** `filesystem` дублирует чтение файлов, `fetch` — загрузку страниц,
   `puppeteer` — `playwright`. Толку нет, шум есть.
4. **Ключи храни в конфиге, не в заметках.** У многих серверов есть API-ключ.
   Он живёт в конфиге MCP и никогда — в коде проекта.

Полезная практика: завести файл `~/.claude/MCP-SERVERS.md` и записывать туда,
**что подключено и зачем**. Через полгода это единственный способ вспомнить,
почему у тебя работает сервер с непонятным названием.

## Как понять, что сервер работает

```bash
claude mcp list
```

Должен показать статус `connected`. Если `failed` — чаще всего одно из трёх:

- не установлен Node.js (`node -v` не отвечает);
- нет интернета или не работает VPN;
- истёк или неверный API-ключ.

Сервер, который не подключился, не ломает работу агента — просто его инструменты недоступны.
