Часть 1. Что установить

Команды ниже — для macOS. Ставим строго по порядку: сначала Homebrew, дальше он поставит почти всё остальное одной строкой. Пункты 1–6 обязательны, 7–8 добавляем, когда освоился. Переключатель в шапке меняет инструкции на Windows.

Команды ниже — для Windows 10/11. Ставим строго по порядку, каждый следующий пункт опирается на предыдущий. Пункты 1–6 обязательны, 7–8 добавляем, когда освоился. Переключатель в шапке меняет инструкции на macOS.

01

Терминал и Homebrew

Windows Terminal

обязательно фундамент

Терминал уже стоит в системе: Cmd + пробел → «Терминал». Homebrew — пакетный менеджер для macOS, через него ставится всё остальное одной командой вместо хождения по сайтам. Скопируй строку целиком, вставь в терминал и введи пароль от Mac (символы не отображаются — это нормально):

/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

Заодно подтянутся Xcode Command Line Tools — без них не работает Git. Установка идёт 5–15 минут. В конце Homebrew напечатает две команды echo ... >> ~/.zprofile — их обязательно нужно выполнить, иначе система не найдёт brew. Потом закрой терминал и открой заново.

brew.sh

Нормальный терминал вместо древней «Командной строки»: вкладки, копипаст, поддержка кириллицы. В Windows 11 уже встроен — просто проверь обновления. Именно отсюда запускаются AI-агенты. Открывается через Win + X → Терминал.

Windows Terminal в Microsoft Store
02

Visual Studio Code

обязательно редактор

Программа, в которой ты пишешь код и внутри которой живут все AI-помощники. Бесплатный, самый распространённый редактор — под него есть всё. Не путай с Visual Studio (это другая, тяжёлая среда для C#).

brew install --cask visual-studio-code

После установки нажми Cmd + Shift + P, набери shell command и выбери «Install 'code' command in PATH» — тогда любую папку можно будет открыть из терминала командой code .

При установке поставь галочки «Add to PATH» и «Открывать через контекстное меню» — потом пригодится.

code.visualstudio.com/download
03

Git

обязательно история версий

Система контроля версий: сохраняет каждый шаг проекта и позволяет откатиться, если нейросеть что-то сломала. Без Git вайб-кодинг превращается в рулетку — это твоя кнопка «отменить» для всего проекта целиком.

В macOS есть старая встроенная версия, ставим свежую:

brew install git
git-scm.com/download/win

После установки один раз представься Git:

git config --global user.name "Ivan Petrov" git config --global user.email "ivan@example.com"
04

Node.js (версия LTS)

обязательно движок + npm

Нужен по двум причинам: на нём работает почти вся веб-разработка и через его пакетный менеджер npm ставятся AI-инструменты, включая Claude Code. Бери версию с пометкой LTS, не «Current».

brew install node
nodejs.org/en/download
05

Python 3.12+

обязательно скрипты, парсеры, AI

Язык, на котором пишут автоматизацию, парсеры, обработку данных и всё, что связано с нейросетями.

brew install python

На Mac команда называется python3, а не python — это нормально, так и должно быть. Встроенный системный Python трогать нельзя, поэтому пользуемся тем, что поставил Homebrew.

В первом окне установщика обязательно поставь галочку «Add python.exe to PATH» — иначе система его не найдёт и придётся переустанавливать.

python.org/downloads/windows

07

Docker Desktop

рекомендую окружения

Docker запускает базы данных, серверы и чужие проекты в изолированных контейнерах — не засоряя систему и не ломая то, что уже стоит. Как только дойдёшь до PostgreSQL, Redis или запуска чужого репозитория, он станет обязательным: вместо часа установок — одна команда.

Для Mac на Apple Silicon (M1–M4) бери сборку Apple Chip / arm64 — Intel-версия будет тормозить:

brew install --cask docker

После установки запусти Docker Desktop из Launchpad и дождись, пока значок кита перестанет мигать. Docker должен быть запущен, иначе команды docker не работают.

На Windows Docker требует включённый WSL 2 — установщик предложит это сам, соглашайся и перезагрузись. После установки запусти Docker Desktop и дождись статуса «Engine running».

Проверка, что всё живо — команда скачает и запустит тестовый контейнер:

docker run hello-world docker.com — Docker Desktop
08

Claude Code

рекомендую AI-агент

Ставится последним, потому что требует Node.js из пункта 4. Это не автодополнение, а агент: сам читает проект, создаёт и правит файлы, запускает команды и проверяет результат. Работает и в терминале, и внутри VS Code через расширение.

npm install -g @anthropic-ai/claude-code

Дальше заходишь в папку проекта, пишешь claude и логинишься подпиской Claude. Расширение для VS Code ставится из панели Extensions по запросу «Claude Code».

docs.claude.com — Claude Code

Всё сразу одной командой. Если Homebrew уже стоит, пункты 2–7 ставятся так:

brew install git node python brew install --cask visual-studio-code docker

Дальше — только настройка Git, галочка code в PATH и запуск Docker Desktop.

Что ставить позже, а не сейчас: Postman (когда начнёшь дёргать чужие API), расширения VS Code — Prettier, ESLint, Python. На старте они только отвлекают.

Часть 2. Проверка, что всё встало

Закрой все окна терминала, открой новое (важно — переменные окружения подхватываются только в новом окне) и выполни команды. Каждая должна вернуть номер версии, а не ошибку.

brew --version # Homebrew 4.x node -v # v22.x.x npm -v # 10.x.x git --version # git version 2.4x python3 --version # Python 3.12+ docker --version # Docker version 27.x

Если терминал отвечает command not found — программа установилась, но оболочка её не видит. Самое частое на Mac: не выполнены две строки echo ... >> ~/.zprofile из шага 1. Выполни их и перезапусти терминал.

node -v # v22.x.x npm -v # 10.x.x git --version # git version 2.4x python --version # Python 3.12+ docker --version # Docker version 27.x

Если команда отвечает «не является внутренней или внешней командой» — программа установилась, но не прописалась в PATH. Самое частое: забытая галочка у Python. Лечится переустановкой с правильной галочкой.

Часть 3. Нейросети для кода

Все они пишут код, но по-разному устроены. Ключевое различие не в «уме» модели, а в форме доступа: автодополнение в редакторе, чат в браузере, агент в терминале или сырой API, за который платишь по факту. Цены — ориентир, тарифы меняются, сверяйся на сайте.

Что выбрать конкретно тебе

Три рабочих связки. Начинать можно с любой — переехать на следующую всегда легко, проект от этого не меняется.

Пока без денег

$0 / мес

VS Code + бесплатный Copilot + Gemini для крупных задач. Полностью хватает, чтобы пройти обучение и собрать первые проекты. Минус — упрёшься в потолок качества на чём-то сложном.

Оптимально для старта

≈ $20 / мес

VS Code + одна подписка Claude и Claude Code внутри. Один инструмент, который делает 90% работы. Именно с этого советую начать, когда готов платить.

Как работаю я

≈ $40 / мес + расход по API

Claude Code как основной агент, ChatGPT/Codex — второе мнение и разбор, DeepSeek по API — на массовую рутину, где переплачивать бессмысленно. Всё в VS Code.

Главная мысль: инструмент не заменяет понимание. Нейросеть уверенно напишет код, который не работает, и так же уверенно объяснит, почему он правильный. Твоя задача на первых месяцах — не научиться быстро генерировать, а научиться читать сгенерированное и замечать, где оно врёт.

Первый проект за 15 минут

Когда всё установлено — открой терминал и пройди пять шагов. Это полный рабочий цикл в миниатюре: папка, история версий, агент, результат, сохранение.

mkdir -p ~/Projects/hello-vibe # создать папку проекта cd ~/Projects/hello-vibe # перейти в неё git init # включить историю версий claude # запустить агента
mkdir C:\Projects\hello-vibe # создать папку проекта cd C:\Projects\hello-vibe # перейти в неё git init # включить историю версий claude # запустить агента

Дальше пишешь агенту задачу человеческим языком — например: «Сделай одностраничный сайт-визитку на HTML и CSS: имя, короткое описание, три ссылки. Тёмная тема, шрифт без засечек. Открой результат в браузере». Он создаст файлы сам.

Когда результат устраивает — фиксируешь его, чтобы было куда откатиться:

git add . git commit -m "Первая версия визитки"

Всё. С этого момента любой эксперимент безопасен: сломал — вернулся к последнему коммиту.

Пять ошибок, на которых спотыкаются все

  • Работать без коммитов Агент за один заход правит десяток файлов. Без Git ты не отличишь, что он улучшил, а что сломал, и не вернёшься назад. Коммить после каждого работающего шага.
  • Ставить задачу одним словом «Сделай сайт» даёт случайный результат. Опиши, что именно, для кого, на чём и как должно выглядеть. Чем точнее вход, тем меньше переделок.
  • Принимать код, не читая Если ты не понял, что делает функция, — попроси объяснить построчно. Непонятый код становится неисправимым багом ровно через неделю.
  • Класть ключи и пароли прямо в код API-ключи хранят в файле .env, а сам .env вносят в .gitignore. Иначе ключ уедет в публичный репозиторий и его найдут за часы.
  • Копить изменения огромными кусками Проси одну задачу за раз и сразу проверяй результат. Двадцать правок за один запрос почти гарантированно приедут с ошибкой, которую потом не локализовать.
