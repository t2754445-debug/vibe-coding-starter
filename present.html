Настраиваем рабочее место

Всё в одном окне: файлы, код, агент, терминал.

Первая команда агенту

Открываем папку starter-kit в VS Code и говорим:

Прочитай SETUP.md и выполни всё, что там написано.

Дальше он ставит всё сам. Твоё дело — отвечать «да».

Что запомнить

  • Терминал открывается Ctrl + ` — клавиша с буквой «ё»
  • Пароль вводится вслепую: символы не показываются. Это нормально
  • Файл CLAUDE.md — правила для агента во всех проектах
Разница между «агент пишет мусор» и «агент пишет то, что нужно» на 80% в этом файле.

Как работает агент

И чем он отличается от чата в браузере.

Чат в браузереАгент в VS Code
ВидитТолько вставленноеВсе файлы проекта
ДелаетПишет текстСоздаёт файлы, запускает команды
ПроверяетНичегоЗапускает и смотрит результат
Агент — исполнитель, а не волшебник. Скажешь «сделай сайт» — сделает какой-то сайт. Он будет выглядеть законченным. И будет не тем.

Практика · первый проект

mkdir -p ~/Projects/hello-vibe cd ~/Projects/hello-vibe code . git init

Дальше задачу агенту — голосом, не печатая:

Сделай одностраничный сайт-визитку на HTML и CSS. Моё имя, короткое описание, три ссылки. Тёмная тема, шрифт без засечек. Открой в браузере.

Важнейший момент занятия

Сохраняем версию

git add . git commit -m "Первая версия визитки"

Это кнопка «отменить» на весь проект целиком.

Проверим на деле

Просим агента всё испортить:

Поменяй всё на розовое и добавь побольше анимации.

Ужасаемся. И возвращаем одной командой:

git checkout .

Вот ради этого и делаются коммиты.

Практика · берём твою настоящую задачу

Помоги продумать программу. Не пиши код. Задача: [рассказываешь своими словами, голосом] Задай мне вопросы, которые нужно прояснить до начала. По одному, жди ответа. Когда вопросов не останется — собери SPEC.md.
Агент задаст вопросы, о которых ты не думал. «А что делать, если в файле дубликаты?» — а ты и не знал, что они там бывают. Ради этого разговора всё и затевается.

Два файла на выходе

SPEC.md

Что программа делает и чего не делает. Поведение, без кода. По этому тексту программу можно написать однозначно.

PLAN.md

Шаги. У каждого — проверяемый результат. Каждый шаг заканчивается чем-то работающим.

git add . && git commit -m "Спецификация и план"

Блок 3 · 45 минут

Где что должно лежать

Архитектура — это не диаграммы. Это ответ на вопрос, кто с кем разговаривает.

Пять принципов

  • 01Раздели ввод, логику и выводПоменялся формат файла — правишь одно место
  • 02Одна функция — одно делоВ описании появилось «и» — надо разделить
  • 03Настройки отдельно от кодаКлючи только в .env, .env только в .gitignore
  • 04Данные в одном местеЛестница: .env → JSON → SQLite → PostgreSQL. Через ступени не прыгать
  • 05Границы с внешним миромВсё, что ходит в сеть, живёт отдельно и предполагает отказ

Три вопроса для проверки

  • Поменяется формат входного файла — сколько файлов править?
  • Можно ли проверить расчёт без Excel и интернета?
  • Найду ли я через месяц главную формулу за минуту?

Эти же вопросы можно задать агенту — раз в неделю, по структуре проекта.

Блок 4 · 55 минут

Собираем программу

По одному шагу из плана. Не больше.

Прочитай SPEC.md и PLAN.md. Сделай шаг 1. Только его. Остановись и покажи результат.

Цикл одного шага

  • 01Попросил сделать один шаг
  • 02Запустил, посмотрел результат своими глазами
  • 03Прогнал на кривых данных
  • 04Запустил ревью вторым агентом
  • 05Попросил объяснить логику простыми словами
  • 06Закоммитил

Ни одного пункта, где нужно уметь читать код.

Читать код не нужно. Нужно ревью. Тот, кто писал код, не может его проверять — он проверяет свою логику своей же логикой. Нужен второй.
/code-review

Ревью вручную · работает в любом агенте

Посмотри изменения, которые мы только что сделали. Найди: ошибки, места, где программа упадёт на нестандартных данных, забытые ключи и пароли в коде, лишние усложнения. Ничего не исправляй. Просто перечисли списком, с файлом и строкой.

Дальше решаешь ты: это почини, это объясни, это не трогай — так задумано.

Обязательная проверка

Ломаем данные специально

Сделай копию моего файла и испорти её: удали пару значений, в одну цену впиши текст, продублируй строку. Прогони программу на копии и покажи, что произошло.
Программа, которая работает только на идеальных данных, не работает.

  • CLAUDE.md — правила поведения агента. Живой файл, дописывается после каждой ошибки
