# Задание для Codex: проверь репозиторий и настрой меня под себя

> **Как этим пользоваться.** Открой VS Code, запусти Codex и отправь ему одно сообщение:
>
> ```text
> Прочитай файл CODEX-START.md и выполни всё, что там написано.
> ```
>
> Если файла на компьютере ещё нет — просто перешли Codex текст этого файла целиком,
> он поймёт задачу и начнёт с загрузки репозитория.
>
> Занимает 10–20 минут. Большую часть времени ты просто отвечаешь «да».

---

## Кто ты в этой задаче

Ты — Codex, работаешь в VS Code на компьютере человека, который **только начинает
и кода читать не умеет**. Это нормально и ничего не меняет в задаче, но меняет то,
как ты говоришь: без жаргона, короткими предложениями, по-русски.
Каждый непонятный термин расшифровывай сразу же, в той же строке.

Не вываливай простыни вывода команд. Прогнал — расскажи словами, что получилось.

---

## Правила на всё время работы

1. **Ничего не удаляй и не перезаписывай молча.** Нашёл существующий файл — сделай копию
   рядом с суффиксом `.backup` и скажи об этом.
2. **Перед каждым шагом, который меняет систему, — одна строка,** что именно сейчас произойдёт.
3. **Наружу ничего не отправляй.** Ни в облако, ни на GitHub, ни в публикацию.
4. **Застрял или что-то не сходится — остановись и спроси.** Не придумывай обходной путь молча.
5. **Ключи, пароли и токены никуда не записывай.** Увидел такое в файлах — скажи, но не копируй.

## Шаг 1. Разберись, где ты и что вокруг

Собери картину и покажи её человеку **одной короткой таблицей**: что установлено,
чего не хватает.

Проверить:

```bash
sw_vers                    # версия macOS
uname -m                   # arm64 = Apple Silicon, x86_64 = Intel
node -v ; npm -v           # движок для агентов
python3 --version          # язык
git --version              # история версий
docker --version           # контейнеры
brew --version             # менеджер программ
code --version             # редактор
codex --version            # ты сам
ls ~/.codex                # твоя папка настроек
```

Каждую строку таблицы дай в формате: **что это** → **стоит или нет** → **зачем нужно**.
Названий команд в таблице не показывай — человеку они ничего не говорят.

Если чего-то не хватает — **пока не ставь**, просто скажи, чего нет
и что без этого не заработает. Ставить будем в шаге 5.

## Шаг 2. Найди или скачай материалы

Тебе нужна папка `starter-kit` из репозитория с материалами.

Сначала поищи её рядом: в текущей папке, в `~/Downloads`, в `~/Projects`, на рабочем столе.
Нашёл — скажи, где именно, и переходи к шагу 3.

Не нашёл — скачай:

```bash
mkdir -p ~/Projects
cd ~/Projects
git clone https://github.com/t2754445-debug/vibe-coding-starter.git
```

Если Git ещё не установлен — скажи об этом человеку и предложи скачать архивом
по ссылке `https://github.com/t2754445-debug/vibe-coding-starter/archive/refs/heads/main.zip`,
дождись, пока он распакует, и продолжи.

## Шаг 3. Прочитай весь набор

Прочитай **полностью**, не по диагонали:

```text
starter-kit/
├── README.md                             как всё устроено
├── SETUP.md                              инструкция на настройку компьютера
├── CLAUDE.md                             ⭐ правила работы агента, главный источник
├── AGENTS.md                             краткая версия тех же правил
├── 01-инструменты/
│   ├── vscode-mac.md                     расширения VS Code
│   ├── mcp-servers.md                    MCP-серверы: что это и какие нужны
│   └── terminal-mac.md                   терминал и Git за семь команд
├── 02-методология/                       ⭐ основная ценность
│   ├── 01-думать-до-промпта.md
│   ├── 02-архитектура-для-начинающих.md
│   ├── 03-выбор-стека.md
│   ├── 04-промпты-для-агента.md
│   └── 05-проверка-без-чтения-кода.md    ⭐ как принимать работу, не читая код
├── 03-скиллы/
│   ├── 01-что-такое-скиллы.md
│   ├── 02-рекомендуемый-набор.md
│   └── примеры/                          два готовых скилла
├── 04-программа/занятие-5-часов.md       план обучения
└── 05-ресурсы/                           подборки и что не вошло в набор
```

После чтения **скажи человеку тремя-четырьмя фразами**, о чём этот набор
и какая мысль в нём главная. Это проверка, что ты действительно прочитал, а не пролистал.

Заодно отметь, если увидишь: противоречия между файлами, устаревшие ссылки,
инструкции, которые на этом компьютере не сработают. Просто перечисли, не исправляй.

## Шаг 4. Собери мои глобальные правила — под себя, а не копией

Главная часть задания.

В наборе лежит `CLAUDE.md` — правила работы, написанные под Claude Code.
Твоя задача — **не скопировать их, а переписать под себя**, потому что ты устроен иначе.

### Куда класть

```text
~/.codex/AGENTS.md
```

Это твой глобальный файл инструкций: ты читаешь его во всех проектах, на любом компьютере
этого человека. Если файл уже есть — **сделай копию** `~/.codex/AGENTS.md.backup`,
покажи, что в нём было ценного, и предложи перенести это в новую версию.

### Что взять из CLAUDE.md по смыслу

- язык общения и оформление ответов;
- «думай до кода»: допущения вслух, развилки показывать, короткий или надиктованный
  запрос — сначала развернуть в постановку задачи и подтвердить;
- простота: минимум кода, ничего впрок, никаких абстракций ради одного случая;
- хирургические правки: трогать только то, что относится к задаче;
- полные пути в ответах, результат открывать локально;
- безопасность: ключи только в `.env`, разрушительные команды — только с подтверждением;
- **проверка без чтения кода** — из файла `02-методология/05-проверка-без-чтения-кода.md`.
  Это важнее всего остального: человек код не читает, значит после каждого шага
  нужно ревью, прогон на кривых данных и объяснение логики простыми словами.

### Что переписать под свои возможности

Не переноси то, чего у тебя нет, и используй то, что есть у тебя:

| В исходном файле | Как должно быть у тебя |
|---|---|
| Пути `~/.claude/` | `~/.codex/`, конфиг — `~/.codex/config.toml` |
| Плагин `/code-review` | Твоя встроенная команда `/review` |
| Скиллы в `~/.claude/skills/` | Твои скиллы в `~/.codex/skills/`, смотреть через `/skills` |
| Упоминания моделей Claude | Твои модели, переключение через `/model` |
| Настройки прав из `settings.json` | Твои режимы одобрения, `/permissions` |

Добавь от себя раздел о твоих командах: `/review` — ревью изменений, `/skills` — что доступно,
`/init` — собрать `AGENTS.md` под конкретный проект, `/status` — что сейчас происходит,
`/mcp` — подключённые внешние источники. Для каждой — одна строка, зачем она нужна человеку.

### Каким должен получиться файл

- **на русском**, короткими правилами, без воды;
- **150–200 строк максимум** — длинный файл ты будешь хуже соблюдать;
- каждое правило формулируй как поведение, а не как пожелание:
  не «старайся писать понятно», а «после каждого шага объясняй, что изменилось, простыми словами»;
- сверху — короткая шапка: что это за файл, где лежит, зачем нужен.

Когда соберёшь — **покажи получившийся файл целиком человеку и объясни,
чем он отличается от исходного**. Только после «да» записывай на место.

## Шаг 5. Доведи окружение до рабочего

Теперь вернись к пробелам из шага 1 и закрой их. Перед каждой установкой — одна строка,
что ставим и зачем. После каждой — проверка, что заработало.

Порядок: Homebrew → Git → Node.js → расширения VS Code.
Что именно ставить — в `starter-kit/SETUP.md` и `01-инструменты/vscode-mac.md`.
Docker, Python, VPN и диктовку человек ставит сам, руками — если их нет,
просто скажи об этом и дай ссылку из `README.md` репозитория.

**Скиллы.** В наборе есть два готовых примера — `explain-me` и `project-start`.
Они лежат в `starter-kit/03-скиллы/примеры/`. У тебя тот же формат: скопируй каждую папку
в `~/.codex/skills/` и проверь через `/skills`, что оба видны. Скажи человеку одной строкой,
что делает каждый.

**Свежая документация библиотек.** Предложи подключить context7 — он даёт тебе актуальные
доки вместо того, что ты помнишь:

```bash
codex mcp add context7 --url https://mcp.context7.com/mcp
```

Ставь только после согласия. Не получилось — не страшно, скажи и иди дальше.

## Шаг 6. Проверь, что всё живое

Сделай маленький учебный проект и пройди по нему полный рабочий цикл — тот самый,
что описан в методике:

```bash
mkdir -p ~/Projects/hello-vibe
cd ~/Projects/hello-vibe
git init
```

Создай простую страничку-визитку, запусти `/review` на изменениях, покажи, что он нашёл,
и сделай первый коммит. Человек должен увидеть весь цикл целиком:
**сделал → посмотрел результат → прогнал ревью → сохранил версию.**

## Шаг 7. Отчитайся

В конце — короткий отчёт, обычными словами, без технических подробностей:

1. **Что нашёл на компьютере** — что было, чего не было.
2. **Что установил** — списком, с одной строкой «зачем» на каждый пункт.
3. **Какие правила себе записал** — три-четыре главных, своими словами.
4. **Что человеку сделать руками** — если что-то осталось.
5. **Что показалось странным** — противоречия в материалах, устаревшие ссылки,
   места, где инструкция не сошлась с реальностью.

И одной фразой: **с чего начать завтра.**

---

## Чего делать не надо

- Ставить всё подряд «на всякий случай». Ставится только то, что названо здесь.
- Менять настройки, о которых не просили: тему VS Code, оболочку терминала, конфиги других программ.
- Пересказывать содержимое всех прочитанных файлов. Прочитал — примени, а не перескажи.
- Молча решать за человека, если что-то неоднозначно. Спроси.
